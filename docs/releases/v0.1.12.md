# Jouzu v0.1.12

This release improves subagent controls and handoffs, preserves automatic work across conversation-tree navigation, and fixes first-use catalog model selection.

## Subagents and delegation

Use `/workflow on`, `/workflow off`, or `/workflow toggle` to control subagents for the session. The Workflow view also has an On/Off control. Turning subagents off stops running and queued children while preserving files already changed and retained results. The setting survives reload and session resume.

Child agents use the model configured for their role. Only you can change that selection in Workflow; the agent-facing tool rejects model overrides. New launches use the configured model, and resumed runs keep their saved model and definition. A role you configure as `same` uses the parent session's model at launch.

Core and JA include `jouzu-delegation`, a skill for writing assignments and follow-ups. Every parent model also receives a short checklist while subagents are enabled: one objective, verified context, constraints, acceptance checks, and an explicit stopping point. The guidance calls for complete sentences and distinguishes provider, tool, instruction, and implementation failures. It does not guarantee that models follow the instructions or improve their performance.

Workflow and subagent summaries show friendly model names. Output previews summarize activity and display readable events. Unread completion results remain deliverable after tree navigation; a complete terminal read suppresses another completion turn only when flow control verifies that the output reached the model.

See [Agents and runs](https://github.com/shisa-ai/jouzu/blob/v0.1.12/docs/subagents.md).

## Goals, tasks, and conversation history

`/goal resume` directly selects a sole saved goal. When there are multiple goals or the target is unclear, the agent uses the conversation and saved goals to resolve it. Resume requests follow normal flow-controlled delivery. Tasks and multiloops reconnect when you navigate the conversation tree. Archiving a multiloop now succeeds on Windows.

With flow control enabled, Jouzu prepares tool history before model admission. A tool call whose result is missing from the selected branch gets an explicit unknown-outcome placeholder. This covers ordinary turns, automatic turns, and built-in model-generated summaries. It does not rerun the tool, copy a result from another branch, or change the saved conversation. Ambiguous or mismatched tool results still block the request. Rewinding history does not undo tool side effects.

The Session Line shows goal, loop, and child-agent activity, with an animated marker while work runs and lifecycle counts. Workspace, Git, runtime, and context information remain in the Status Bar.

## Catalog startup

An enabled catalog with an available credential but no activated revision refreshes before initial model selection, with an eight-second budget and a `Fetching model catalog…` notice. Existing catalogs keep serving cached models while refreshing in the background. Failed refreshes and malformed catalog configuration do not prevent startup.

## Installation

Update an npm installation with `npm install -g jouzu`, or use Jouzu's automatic updater. This release also provides an unsigned Windows x64 installer preview. See [Windows installer preview](https://github.com/shisa-ai/jouzu/blob/v0.1.12/packaging/windows/README.md) for installation, rollback, and the `/LOG` flag for diagnosing activation failures.

## Testing limits

Automated tests cover role-model restrictions, skill delivery, notification receipts, tree navigation, history preparation, and catalog startup. They do not measure delegation quality or establish live-provider recovery behavior. Windows installer acceptance covers Windows Server 2025 x64; clean Windows 10/11 testing remains pending. The installer is unsigned.
