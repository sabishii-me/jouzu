# Jouzu v0.1.17

This release adds a work dashboard above the prompt, automatic session and pane
labels, and a redrawn prompt frame.

## Work dashboard

The dashboard reports work that is running, waiting, or finished. Each producer
gets a section opened by a divider carrying that section's counts and route:

```text
── Agents · 1 done · !1 ────────────────────────────────────────────────────
  ! coder · unread result · 3m · Run the shell command `sleep 180` and then…
  ✔ reviewer · 4m
── Tasks · 1 running · 1 open · 2 done ─────────────────────────────────────
  ⠋ #6 Integrate dashboard rendering
  ○ #7 Qualify and document
```

- A row carries the state marker shared with the Session Line, the producer kind,
  the elapsed time, and a detail field: the current tool and its arguments for a
  running child, `exit 2` for a failed job.
- A finished child whose result the model has not read raises an attention row
  and a count. The row leaves the panel 30 seconds after it appears; the count
  stays until the result is read. Reading the result through `subagent read`
  clears it, delivery alone does not.
- Compact mode shows five lines and expanded mode ten, both capped at one third
  of terminal height. Settings holds the mode. Hiding the dashboard for a session
  does not change the saved mode, and a malformed policy file is reported and
  preserved rather than replaced.
- Rows stop animating while the session streams and while the dashboard is
  hidden. Elapsed time still refreshes.
- A section that runs out of room collapses to its divider, which keeps the
  counts and the route.

Child agents, tasks, and flow alerts use the dashboard. Background jobs and loops
keep their own panels: those producers publish rows only after confirming,
through a widget claim, that their native panel is hidden, and the pinned
versions do not implement that interface. No item is shown twice.

The height measurement reads Pi's interactive root order, and
`scripts/check-pi-contract.mjs` asserts that order, so a Pi upgrade fails
qualification instead of silently dropping the panel.

## Session and pane labels

Automatic naming is on by default and runs after the first completed task turn,
using the selected provider/model. The naming route is fixed at the first
request, so switching the conversation model does not change it.

- `/labels` reports status and the command list without changing anything.
- `/labels on` and `/labels off` set the session switch. A saved `off` stays off
  when the session is reopened.
- `/labels global on|off` sets the persistent switch shared with Settings →
  **Auto labels**. Both the global and session switches must be on for naming.
- `/labels pin` and `/labels auto` protect or release the session name. `/name`
  also pins it.
- `/labels pane pin` and `/labels pane auto` protect or release the pane title.

A session name is at most 60 characters. A pane label is at most 12 lowercase
ASCII letters, digits, or hyphens. Session IDs, filenames, workflow lanes, and
tmux window names do not change. Stock tmux and Byobu status formats show an
owned label without renaming the window, and an existing title that Jouzu does
not own is left alone.

Global settings live in `session-labels.json` under Jouzu's configuration
directory; a malformed file disables naming and is not overwritten. Session
choices and pane pins are saved in the session transcript. See
[Session labels](https://github.com/shisa-ai/jouzu/blob/v0.1.17/docs/session-labels.md).

## Prompt frame

The prompt rail and the background fill that replaced it are gone. The frame
draws a single `❯` on the first prompt row and a blank gutter of the same width on
continuation rows, so selecting a wrapped prompt in the terminal picks up at most
one marker character instead of one per row. The editor renders at two columns
less than the frame width.

The model label uses the same teal as the prompt leader; the provider stays dim.
The thinking suffix turns teal with the model name.

## Fixes

- **Optional fields are declared nullable.** Optional subagent fields and
  `agent_wait` arguments are declared nullable at registration, and an explicit
  `null`, an empty string, and the documented `none` sentinel for `replaceToken`
  are read as omission. A provider that requires every declared property no
  longer forces a model to supply a placeholder value for a field it meant to
  omit. Authority checks, required fields, and unknown-field rejection are
  unchanged.
- **Subagent argument errors name the recovery.** An operation-specific input
  that does not fit the operation is refused with the field and the recovery,
  and launch context is ignored on operations other than launch and resume.
- **A task package source mismatch explains how to recover.** When the pinned
  task package's source hash differs, the diagnostic says to preserve local edits
  and reinstall the pinned package. The overwrite guard is unchanged.
- **Task continuations keep Jouzu's flow ownership** while adopting upstream
  `@lhl/pi-tasks` `a07c749`. Continuation identity uses custom-message metadata
  rather than prompt text, cancellation context survives a thrown abort, the tree
  reconnection anchor is repaired, and an upgrade from an older pin is refused
  rather than applied as a lifecycle-only change.
- **Native provider requests are no longer capped at 8 MiB.** A session history
  carrying images is sent whole. Explicit byte budgets and automatic-result
  limits are unchanged.
- **Astra diagnoses and repairs by default** when you point out a problem, and
  keeps its scope for diagnosis-only and review-only requests.
- **Dashboard counts and polling.** The Session Line child count counts queued
  and running children from the child source only, disabled flow control reports
  nothing pending so earlier alerts clear, idle flow state is polled every five
  seconds instead of every second, and source polls coalesce during an active
  read.

## Installation and testing limits

Update with `npm install -g jouzu@0.1.17` or Jouzu's updater.

Dashboard coverage uses fixtures and one live qualification in tmux at 137x67.
Expanded mode, the Settings route on short terminals, resizing, streaming-session
animation, the loop producer, voice input, a multiline editor, and Windows or
macOS terminal behavior are unqualified. Session-label coverage uses fixtures and
live tmux windows and does not establish naming quality for every repository or
query shape.

Two flow-control refusals are recorded and unresolved in this release. A
scheduled-prompt wake turn carries no owning work, so a command the background
extension would auto-background, `bg_task`, and `schedule_prompt` are refused in
that turn and succeed in the next host turn. A tool call that outlives the
invocation holding its work is refused as inactive, and succeeds when reissued.

The Windows installer preview remains unsigned, and clean Windows 10/11 installer
acceptance is separate from CLI qualification.
