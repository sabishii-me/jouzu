# Jouzu v0.1.11

This release improves Windows installation and update discovery, adds goal controls, and fixes flow recovery and saved-login model access.

## Windows installer

The launcher shows the working folder before opening a terminal and can remember it for later launches. If the folder becomes unavailable, it asks for another folder. The launcher, shortcuts, and installer use the JZ icon.

The working-folder screen checks GitHub Releases at most once per 24 hours. When a newer stable x64 installer is available, **Download update** opens its download in your browser. Run the downloaded installer to upgrade.

After extraction, the installer shows an animated progress bar and the step it is running. Activation checks startup files and tests the CLI before switching versions, avoiding a full read and hash of every bundled file. Startup-file checks and the started CLI probe each have a 30-second limit. Full diagnostic verification remains available with `JouzuConsole.exe --verify`, which shows file-count progress.

Download the `JouzuSetup-…-x64-unsigned.exe` asset from this release. Windows may show an unknown-publisher warning. See [Windows installer preview](https://github.com/shisa-ai/jouzu/blob/v0.1.11/packaging/windows/README.md) for setup, repair, and rollback instructions.

## Goals and flow recovery

Use `/goal` to list running and paused goals. `/goal pause`, `/goal stop`, and `/goal resume` accept an optional `lane/run-tag`; without one, they select the attached goal or the only matching goal. `/multiloop` shows all runs.

Automatic work continues across compaction, including compaction that retains no original transcript tail. Recovery preserves delivered input and pending work. `/flow` reports held work, the failed stage, the owning task and dependencies, and the original failure after a reset. Task completion returns tool authority to the invoking work.

## Catalogs and web results

`/login shisa` supplies catalog models using the saved login without requiring a separate environment key or catalog token. Catalog failures report the cause and a suggested action, including authentication, DNS, proxy, certificate, and local storage errors. `catalog status` retains the last refresh error until a refresh succeeds.

`batch_web_fetch` shows a row for each URL with its status, elapsed time, and extracted size.

## Testing limits

Native Windows Server 2025 tests cover launcher behavior, release discovery, activation checks, and progress visibility. Clean Windows 10/11 testing, visual scaling, desktop proxy authentication, and live model access remain unverified. The installer preview is unsigned.

Flow recovery has unit and assembled-session coverage; live-provider recovery after compaction remains unverified. Catalog error handling has loopback fixture coverage.
