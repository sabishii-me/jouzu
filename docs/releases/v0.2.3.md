# Jouzu v0.2.3

Jouzu v0.2.3 adds an extension API for authenticated human input and fixes command navigation, recovery holds, Japanese command entry and prose wrapping, and Windows settings saves.

## External user-input adapters

Extensions can register `pi.registerUserInputAdapter` to deliver authenticated human text with user-input ordering, target-scoped bindings and durable delivery receipts. Registration requires an explicit grant in the agent configuration directory. Each integration supplies its own authentication, transport and access controls; the API is not a sandbox for installed extensions.

Messages retain the branch target selected when the person sends them. Slash-prefixed text stays literal, and reconnecting clients can look up delivery receipts without resending consumed or uncertain messages. A consumed receipt means the input was accepted, not that the provider or requested work succeeded.

See [External user-input adapters](https://github.com/shisa-ai/jouzu/blob/v0.2.3/docs/user-input-adapters.md) for authorization, lifecycle rules, limits and the example extension.

## Commands and recovery

- Extension commands can await tree navigation and continue on the selected branch. Busy navigation is refused before callbacks or branch changes, and previously captured input stays bound to its original branch.
- Local commands such as `/flow` and `/about` leave automatic replies paused when recovery or a request is holding model input. A command waiting for recovery state does not start if its session was replaced or its branch changed.
- Input that is not a recognized command, including unknown names and prompts sent with template expansion off, receives ordinary recovery checks. Interactive submission trims surrounding whitespace before command dispatch; leading spaces do not quote a command.
- RPC end-of-input drains accepted commands, resolves unanswered dialogs to their defaults and reports unfinished commands or shutdown failures once within bounded shutdown periods. A final command without a trailing newline still runs.

See [Flow control](https://github.com/shisa-ai/jouzu/blob/v0.2.3/docs/flow-control.md) and [RPC mode](https://github.com/shisa-ai/jouzu/blob/v0.2.3/docs/diagnostics.md#rpc-mode).

## Japanese input and display

- Use a leading full-width slash (`／`) for interactive commands and completion, including queued follow-ups. Command names and arguments are not Unicode-normalized. RPC and external adapter input keep the full-width slash literal.
- Japanese Markdown prose wraps at punctuation-aware boundaries while preserving explicit line breaks, styling, links and inline literals. Code blocks and tables keep their own wrapping behavior.
- Missing shortcut hints, model labels, Catalogs labels and active counts use Japanese when selected.
- Settings keeps the selected row in place when moving focus expands or collapses catalog details.

See [Language and locale](https://github.com/shisa-ai/jouzu/blob/v0.2.3/docs/language.md). Japanese remains a preview. Automated editor and renderer tests do not establish native input-method or visual behavior in every terminal.

## Installation and account setup

- Retry transient Windows file-replacement failures when saving private state, including language preferences, without deleting the existing file.
- Show a link to Shisa signup offers and eligibility instead of fixed credit amounts. Settings reports account connection status separately from offers.

Install or update with:

```sh
npm install -g jouzu@0.2.3
jz doctor
```

Jouzu remains beta software. Native Windows qualification uses Windows Server 2025; it does not establish clean Windows 10/11 behavior on every configuration.
