# Jouzu v0.1.9

Unreleased.

This release adds Shisa account sign-in, coordinates automatic work by default, and expands catalog settings and diagnostics. TextGuard delivers flagged web results with findings attached while keeping flagged skills behind approval.

## Shisa account and voice

Run `/login shisa` and approve the connection in your browser. Jouzu saves a dedicated API key for inference, the Shisa model catalog, and voice. Voice uses the speech endpoint returned by sign-in. `SHISA_API_KEY` takes precedence; the catalog also accepts a separately saved catalog token before using the login.

Jouzu writes the key and device link before acknowledging delivery. If storage fails, delivery stays unconfirmed. If acknowledgement retries fail, Jouzu asks you to sign in again.

`/logout shisa`, or selecting Shisa in `/logout`, attempts to revoke the device key at the gateway that issued it, then removes local credentials and link state. Network failure still leads to local cleanup and dashboard disconnect instructions. A link saved without its issuing gateway also needs dashboard disconnect. Local storage failures are reported separately.

Logout cancels voice recording, discards uninserted text, and removes Shisa catalog models. Other provider credentials and environment variables remain unchanged. Jouzu suppresses Shisa access in that process until another successful login; unset `SHISA_API_KEY` before restarting to stay signed out.

## Automatic work and recovery

Session flow control is on by default:

- Background completions wait for the active turn and queued messages, then arrive in batches.
- Waits record dependencies and deadlines. Background tasks with a health policy can report whether their process is still alive.
- Other automatic work, including child-agent completions and scheduled prompts, waits while a dependency wait is active.
- Interrupting a turn pauses automatic work until your next message or `/flow resume`.

`/flow` shows held work, waits, reasons, deadlines, and recovery commands. Its output stays in the terminal and adds nothing to the model's context.

| Command | Effect |
| --- | --- |
| `/flow pause` / `/flow resume` | Hold or release automatic turns for the session |
| `/flow pause <work>` / `/flow resume <work>` | Hold or release one goal or measured loop |
| `/flow stop <work>` | End automatic turns and waits for the named work; already running jobs continue |
| `/flow cancel <token>` | Cancel a wait without stopping its job |
| `/flow retry <request>` | Retry one withheld request against its unchanged input |
| `/flow resolve <attempt> retry\|discard` | Decide whether to retry a turn whose provider outcome is unknown or mark it spent; retry may repeat an answered turn |
| `/flow reset` (alias `/flow clear`) | Release a stuck turn while idle; preserve running jobs and execution records |

Use the identifiers printed by `/flow`. Set `JOUZU_FLOW_CONTROL=0` before launch to disable flow control for that process. Retained flow-control history has fixed limits; records needed to explain held work are kept.

## Catalog settings and diagnostics

Settings / Catalogs can save a bearer token with private file permissions. The configured environment variable takes precedence over that token. A source can be saved before its credentials are available; Jouzu warns and waits to contact it. Removing a source or switching its authentication to none deletes the saved catalog token.

The **Maximum context** row sets a global ceiling: 128K, 192K, 256K, 384K, 512K, 768K, 1M, or off. Focus it with `↑` from the first source, then change it with `←` or `→`. Compaction, context usage, and model-switch checks use the smaller window. An explicit local `modelOverrides.contextWindow` takes precedence. Turning the ceiling off restores declared windows.

`jz doctor` summarizes catalog gaps; `jz catalog status` lists affected offerings:

- Missing input types or token limits prevent an offering from adding a model, though it can still update a matching existing model.
- Missing thinking levels limit Jouzu's reasoning controls. Offerings that explicitly declare no reasoning support are excluded from this warning.

These diagnostics inspect cached catalogs. Run `jz catalog refresh` to check a server update. Jouzu accepts recognized thinking levels from a catalog and ignores unknown names. Explicit per-model preferences take precedence over catalog defaults.

## TextGuard review

By default, flagged web results reach the model with findings attached and instructions to treat the content as untrusted data. Flagged skills stay withheld until approval. `/textguard strict` withholds all flagged input; `/textguard off` disables scanning for the session; `/textguard on` restores the default. Child agents inherit the parent's mode.

Withheld content and delivery with error-level findings each produce a notification, once per piece of content. `/textguard` opens the decision list; `/textguard reports` lists informational and warning reports. The detail view shows finding locations and the content with control and invisible characters escaped.

**Allow for this session** admits the content for the session. **Always allow this exact content** saves approval across restarts. Changed content, scanner, or policy requires another decision. Child agents cannot create approvals or inherit the parent's approvals. An interrupted check can be approved if the full content was captured and identified. See [TextGuard scanning](https://github.com/shisa-ai/jouzu/blob/main/docs/textguard.md) for scope and limits.

## Fixes and other changes

- Advance task lists through their remaining work by default unless interrupted. `TaskReorder` changes run order; `TaskList` shows the next task.
- Preserve the prompt editor and flow control when replacing a session. Interrupted turns keep queued user messages pending.
- Retain unread background summaries after clearing a task, stop reporting delivered input as held, and recover interrupted or partially recorded requests.
- Release goal work after local commands finish.
- Serialize Camoufox fetch and search calls to prevent shared-page conflicts.
- Give child agents the parent's model-specific guidance, accept per-run model overrides, and show provider errors when a run fails. Ambiguous model names require the full `provider/model`.
- Let RPC sessions finish an accepted prompt after end-of-input. Preserve machine-readable Pi output byte for byte.
- Present diagnostics and configuration plans with consistent headings, aligned values, and problems first. Status remains readable without color.
- Serialize source builds, skip unchanged extension-bundle installs, check Go before building, and use Windows' built-in `tar.exe` for extraction.

## Testing limits

Flow-control tests substitute providers; live workloads still need qualification. Shisa authentication tests substitute remote services, and voice still needs live microphone, permission, and transcription checks. These tests do not establish that the deployed Shisa catalog supplies every required model field. See [Testing](https://github.com/shisa-ai/jouzu/blob/main/docs/testing.md) for the suites and opt-in live checks.
