# Jouzu v0.2.0

Jouzu v0.2.0 upgrades the embedded Pi runtime to 1.0.0, adds a signed Windows launcher, and adds flow-control, agent-workflow, and installation improvements.

## Changes

- Use Pi 1.0.0 with Jouzu's existing tools, work dashboard, and regular/fullscreen interfaces. Saved settings, sessions, and background work are preserved.
- Keep GPT-6 Astra requests compatible with API-key and ChatGPT sign-in authentication, including prompt-cache settings.
- Prevent rejected tool-result metadata from bypassing TextGuard checks, including calls made through another tool.
- Recover interrupted flow-journal repairs without losing completed records or blocking session reopening.
- Store flow journals as journal and scalar records with crash recovery and compatibility coverage.
- Keep running agents visible in the dashboard and Workflow.
- Run child writers in parallel by default. Child concurrency and workspace sharing are settings.
- Scope agent file searches to relevant project paths.
- Resume resolved waits after abandoned input, and keep autonomous loops moving after task waits.
- Use bundled TypeBox and resolve native canvas dependencies when an npm installation fails.
- Prioritize Shisa in the CLI login provider menu.
- Install the Windows launcher from [GitHub Releases](https://github.com/shisa-ai/jouzu/releases) with onboarding, a workspace screen, component management, diagnostics, logs, terminal access, Git Bash support, and recovery controls. It bundles Node, pnpm, PortableGit, and Windows Terminal.
- Keep the README focused on getting started, with detailed guides in the [documentation index](https://github.com/shisa-ai/jouzu/blob/v0.2.0/docs/README.md).

## Update

```bash
npm install -g jouzu@0.2.0
```

Global npm installations also update through Jouzu's updater. Existing sessions and flow records need no manual conversion.

## Limits

The embedded Pi runtime stays at 1.0.0. Pi 1.1.0 and 1.2.0 are deferred to a later release, and upstream stopped publishing the `gitHead` field that Jouzu pins releases by, so those versions cannot be adopted until that is resolved.

Three transitive dependency advisories are carried forward unchanged from v0.1.18: `proxy-addr` (critical), `@modelcontextprotocol/sdk` (high), and `brace-expansion` (high). `npm audit` reports them in the installed tree. The first two come from the bundled `pi-webaio` extension.

Live official Astra authentication and physical-terminal behavior in both display modes remain separate from fixture coverage.

The signed Windows launcher and Jouzu update recipes are built from the same source tag and published after the npm package. The Launcher version line is independent of the npm version.
