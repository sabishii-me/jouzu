# Jouzu v0.1.18

This release moves background jobs into the work dashboard and removes the
flow-control refusals that blocked tools on a turn without an owning work item.

## Background jobs in the dashboard

Background jobs publish rows into the work dashboard instead of their own inline
panel. The producer claims the dashboard first and hides the native panel only
while the claim is held, so a job appears once and no job is hidden when the
claim is released.

The background-job manager is unchanged: `/bg` or `Alt+Shift+H` opens it, and
`/bg watch <task>` opens it focused on one job. Visibility preferences, manager
commands, and shortcuts keep working while the inline panel is suppressed. Loops
keep their own panels.

## Work attribution is not a tool permission

Attribution records which user, task, or goal a turn is working on so waits,
background jobs, and derived work name a sensible origin. It does not grant or
withhold access to a tool. The flow-control refusals recorded in v0.1.17 are
resolved:

- A turn that carries no user or task work no longer refuses `bg_task`,
  `schedule_prompt`, a command the background extension would auto-background, or
  `subagent` launch and resume. Each falls back to the host work registered when
  the branch attached.
- A tool call that outlives the invocation holding its work is no longer refused
  as inactive.
- `agent_wait` reads its `work` field as attribution. Omit it or pass `null` to
  wait as the current task or session. A task can wait on any execution
  registered in the same branch, including another task's job.

Exact producer, handle, and execution identities are still required, so a wait
cannot observe the wrong job. An unregistered work identity is still refused.

## Wait and task handoff fixes

- An exact live `replaceToken` replaces a wait after task attribution changes. A
  different live wait on the destination task is not displaced, and a finished or
  retired token is still refused.
- A paused task keeps its wait association, so resuming does not duplicate the
  wait and stopping the task cancels it.
- A completed task continuation restores its live creation origin, so the next
  task acquires execution authority without borrowing unrelated or stale work. A
  newer task selection is kept when an older completion returns.
- Work selection is rechecked after attempt reads, before unclassified fallback,
  and after automatic authority preparation, so a selected turn cannot migrate
  between attachments.
- A running loop is re-driven after a non-loop turn while user suppression is
  preserved, and a requested compaction's continuation registers host work so the
  continuation's tools run.

## Execution and recovery guidance

The model guidance now states that a failed check or an unsuccessful first
attempt is an intermediate result, not completion. The agent is asked to make
authorized in-scope repairs, rerun the affected checks, keep the original
deliverables active across prerequisites, apply a steering instruction in the
same turn, and name the exact dependency when progress needs user input or an
unavailable external resource. Review-only and diagnosis-only requests keep their
stated boundary, and a dependency wait is not reported as task completion.

These are behavioral instructions, not a runtime guarantee. Prompt-delivery tests
verify that the text reaches main and child sessions; they do not measure whether
a model follows it on a coding task.

## Installation and testing limits

Update with `npm install -g jouzu@0.1.18` or Jouzu's updater.

Background-job dashboard rows are covered by fixtures and the bundled background
extension's lifecycle regressions, which run without a terminal. Live
background-job rendering in a terminal, loop rows, and macOS and Windows terminal
behavior are unqualified. The v0.1.17 dashboard coverage limits still apply to
expanded mode, the Settings route on short terminals, resizing, and
streaming-session animation.

The Windows installer preview remains unsigned, and clean Windows 10/11 installer
acceptance is separate from CLI qualification.
